# 주간 해외 동향 리포트

USMEF Korea 뉴스라인 1페이지의 PDF를 모두 읽어 미국 소고기 시장 데이터를 Excel 파일로 저장하는 Python 프로그램입니다.

생성되는 Excel의 열은 아래와 같습니다.

- `구분`: 뉴스라인의 발행일(최신순)
- `도축두수`: 미국 소고기 주간 도축두수(천두 단위)
- `미국($/lb)`: Choice 등급 소고기 컷아웃 가격(달러/파운드)

## 준비물

- Python 3.10 이상
- 인터넷 연결

## 설치 및 실행

PowerShell 또는 터미널에서 프로젝트 폴더로 이동한 뒤 아래 명령을 순서대로 실행하세요.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

실행이 끝나면 다음 파일이 생성됩니다.

```text
output/usmef_weekly_market_report.xlsx
```

뉴스라인 PDF는 먼저 내장 텍스트에서 필요한 숫자를 읽습니다. 텍스트가 없는 일부 이미지형 호만 한국어 OCR로 자동 전환하므로, 일반적인 주간 현행화는 훨씬 빠르게 처리됩니다. 처음 OCR이 필요한 실행에서는 모델 준비에 시간이 조금 더 걸릴 수 있습니다.

## 웹페이지로 실행하기

```powershell
.\.venv\Scripts\Activate.ps1
python app.py
```

브라우저에서 `http://127.0.0.1:5000`을 열고 **보고서 생성** 버튼을 누르세요. 업로드한 양식의 비어 있는 주차 행을 찾아 다음 항목을 현행화합니다.

- `소-미국`, `돼지-미국`: 다음 주 수요일 USMEF 뉴스라인의 도축두수와 컷아웃 가격
- `소-호주`: MLA의 주간 소 도축 합계, Eastern States Young Cattle Indicator(EYCI), AUD/KRW 환율
- `돼지-EU(독일)`: AHDB 원본 Excel의 `Week ended` 날짜와 일치하는 독일 Grade E 가격(유로/100kg)
- `계란-일본`: 주차 행의 날짜와 일치하는 JA 전농타마고 도쿄 M란 기준치(엔/kg)
- `계란-미국`: USDA Market News의 6-Area 주간 재고량과 National Shell Eggs - Caged Large 평균가격
- `닭-미국`: USDA Market News Slug ID `3208`의 Chicken (Young) 주간도축량과 Slug ID `3646`의 National Composite WOGS `Wtd Avg` 가격(cents/lb)
- `닭-브라질`: CEPEA 동결 닭고기 가격 시리즈의 동일 날짜 `À vista R$` 가격과 BRL/KRW 환율

### 해외 축산 동향 기사 초안 12종

웹페이지의 **기사 초안** 탭에서 소·돼지·닭·계란별 현지동향 2개와 국내기사 1개, 총 12개 항목을 처리합니다.

| 축종 | 첫 번째 현지동향 | 두 번째 현지동향 | 국내기사 |
|---|---|---|---|
| 소 | 미국 · USMEF 뉴스라인 소고기 시장동향 | 호주 · MLA Latest News | 해외 소고기 관련 한국어 보도 |
| 돼지 | 미국 · 같은 USMEF의 돼지고기 시장동향 | EU(독일) · EuroMeatNews | 해외 돼지고기 관련 한국어 보도 |
| 닭 | 미국 · Brownfield Ag News | 브라질 · AviSite | 해외 닭고기 관련 한국어 보도 |
| 계란 | 미국 · Brownfield Ag News | 일본 · JA 전농·전농타마고 뉴스 및 공개 리포트 | 해외 계란 관련 한국어 보도 |

기사 초안의 보고 기준일 기본값은 **오늘 날짜**입니다. 날짜를 직접 선택하면 선택값은 다른 작업 탭을 오가도 유지됩니다.

기사 기간은 **보고 기준일이 속한 주의 일요일~토요일(양 끝 날짜 포함)**입니다. 예를 들어 2026-10-01(목)을 선택하면 2026-09-27~10-03에 발행된 기사만 확인합니다. 12개 항목의 지정 매체·NAVER·Google 등 보완 검색에 동일하게 적용하며 보고일 이후라도 같은 주의 금·토요일을 제외하지 않습니다. 아직 오지 않은 날짜의 기사는 공개된 후 다시 실행하면 확인할 수 있습니다. 지정 매체에 적합한 원문이 없으면 Google News RSS 및 일반 공개 Google 검색 결과로 보완합니다. 검색 결과나 헤드라인만으로 초안을 쓰지 않고, 실제 원문의 발행일·본문·언어·국가·축종을 확인합니다. 로그인, Cookie, 접속 제한 우회는 사용하지 않습니다.

국내기사는 **NAVER 뉴스 API를 우선** 사용합니다. 재발급한 인증정보를 프로젝트 루트의 비공개 `.env`에 아래 변수명으로 넣고 서버를 다시 시작하세요. 값은 채팅·소스·GitHub에 올리지 않습니다. NAVER가 연결되지 않거나 적합한 후보가 없으면 공개 Google 뉴스로 보완하지만 검색 결과를 확보하지 못할 수 있습니다.

```dotenv
NAVER_CLIENT_ID=발급받은_Client_ID
NAVER_CLIENT_SECRET=발급받은_Client_Secret
```

수집·요약 처리량 기반 진행률과 전체 경과시간을 표시하며, 완료된 초안부터 카드에 나타납니다. **보고서 문구 복사**는 완료된 항목만 소→돼지→닭→계란 순서로 복사합니다. 현지동향은 `-(현지동향) 요약`, 국내기사는 `∙ “제목”(매체,월.일.)`와 다음 줄 `- 요약` 형식입니다.

### 완료된 기사 초안을 한글 보고서에 반영

1. **보고서 생성**에서 가격·표·그래프가 현행화된 HWPX 파일을 내려받습니다.
2. **기사 초안**에서 같은 주차의 보고 기준일을 선택해 기사를 찾고 완료된 초안의 원문을 검토합니다.
3. 상단 **기사 초안을 한글 보고서에 반영** 영역에 해당 HWPX를 선택하거나 드래그합니다.
4. **기사 반영 한글파일 다운로드**를 누르면 8개 현지동향과 4개 국내기사 제목·출처·요약이 해당 위치에 들어간 새 파일을 받습니다. 원본 파일은 바뀌지 않습니다.

현재 화면의 완료 초안을 사용하므로 기사 재검색이나 AI 재요약을 하지 않습니다. **완료된 초안이 1개 이상이면 부분 반영도 다운로드할 수 있습니다.** 미완료 항목의 기존 제목·요약은 지워 빈칸으로 두며(양식 기호는 유지), 화면에 반영 건수와 빈칸 건수를 표시합니다. 모두 미완료이거나 작업 중이면 반영하지 않습니다. 가격값·표·그래프·문서 기준일은 그대로 보존하며 기사 문단만 교체합니다. 이 단계는 HWPX ZIP/XML을 직접 편집해 한글·Excel 실행이 필요하지 않습니다. 구형 `.hwp`는 한글에서 `.hwpx`로 저장한 뒤 올려 주세요. 국가·축종별 기사 위치가 빠진 다른 양식이나 잘못된 완료 초안은 반영하지 않고 안내합니다. 업로드는 요청 전체 20MB 이하이며, 완료된 원문 날짜는 선택 주의 일요일~토요일 범위여야 합니다.

기존 **보고서 문구 복사**도 계속 사용할 수 있습니다. 날짜·파일·초안을 변경하면 이전 반영 결과를 해제하며, 재다운로드 링크와 성공·실패 메시지는 업로드 영역에서 바로 확인할 수 있습니다.

보고서용 한 줄 문장을 자동으로 만들려면 이 PC에 [Ollama](https://ollama.com/download)와 로컬 모델이 필요합니다. 설치 후 PowerShell 또는 명령 프롬프트에서 한 번만 실행하세요.

```powershell
ollama run qwen2.5:3b
```

`qwen2.5:3b`는 내부 사고문을 생성하지 않아 보고서용 짧은 문장에 적합한 기본 모델입니다. 메모리가 적으면 `qwen2.5:1.5b`를 받은 뒤, 앱을 시작할 때 아래처럼 모델 이름을 지정할 수 있습니다.

```powershell
$env:OLLAMA_MODEL="qwen2.5:1.5b"
python app.py
```

Ollama는 기사 원문을 이 PC의 `127.0.0.1:11434` 로컬 서버에만 전달합니다. 기사 후보·초안 결과는 선택한 보고 기준일별로 현재 브라우저에 저장되며, **보고서 문구 복사** 또는 **기사 반영 한글파일 다운로드**로 한글 보고서에 옮길 수 있습니다. 기사가 아직 없거나 발행사 페이지가 일시적으로 열리지 않으면 다음 실행 때 다시 확인합니다.

독일 가격의 `유로/kg`은 `독일 ÷ 100`으로 계산해 소수 둘째 자리까지 반올림합니다. 환율을 수집하는 모든 시트의 USD·EUR·JPY·BRL·AUD 매매기준율은 네이버 증권에서 가져옵니다. 기준일 값이 있으면 그대로 사용하고, 주말·휴장일 등으로 값이 없으면 기준일 이전의 가장 최근 게시 값을 사용합니다. 이전 값도 없으면 해당 행을 보류하며 미래 값이나 0으로 대체하지 않습니다. 기존 환산식과 JPY의 100엔 기준은 유지합니다. 생성한 파일은 브라우저 다운로드 폴더와 프로젝트의 `output` 폴더에 저장됩니다.

### 한글 보고서 표 현행화

Excel 생성이 끝나면 같은 보고 주차(가장 최근 목요일 기준)의 값이 한글 보고서 양식의 8개 표에도 자동으로 입력됩니다.

- 소고기: 미국·호주
- 돼지고기: 미국·EU(독일)
- 육계: 미국·브라질
- 계란: 미국·일본

표 안의 `2025년`, `2026년 전주`, `2026년 이번 주`, 전주·전년 대비, 원화 환산 값만 바뀝니다. 제목, 본문 문장, 뉴스 문구, 그림과 그래프는 이번 단계에서 그대로 둡니다. 다운로드 영역에서 **Excel 현행화본**과 **한글 표 현행화본**을 각각 받을 수 있습니다.

이 기능은 로컬 Windows에서만 동작하며 아래가 필요합니다.

- 한글(Hancom Office) 2020 이상 설치
- 프로젝트의 `report_template/weekly_overseas_market_report_table_template.hwp` 양식 파일 유지

한글 프로그램이 설치되지 않은 PC 또는 Render 같은 Linux 서버에서는 Excel 생성은 가능하지만 한글 표 현행화본은 만들 수 없습니다.

계란-일본 시트는 `일본(엔/kg)`이 비어 있는 지난 주차만 찾습니다. 해당 날짜의 도쿄 M란 기준치를 입력하고, 네이버 증권의 JPY/KRW 매매기준율(100엔 기준)을 `환율(1엔=x원)` 열의 기존 양식 방식에 맞춰 입력합니다. 원화 가격은 기존 `일본(엔/kg) × 환율 ÷ 100` 계산식으로 갱신됩니다.

계란-미국 시트는 주차 행의 금요일 기준으로, 같은 주 월요일의 USDA Slug ID `1427`에서 첫 표 `Total / Total / 6-Area Total` 재고량을 가져옵니다. 같은 금요일에 발행된 Slug ID `2848`에서는 첫 표 `National Shell Eggs - Caged`의 `Large / Average Price`를 가져옵니다. USD/KRW 매매기준율을 함께 입력하며, 양식에 있던 단위·원화 환산 계산식은 그대로 유지됩니다.

닭-미국 시트는 주차 행의 날짜와 같은 날 발행된 USDA 보고서를 사용합니다. Slug ID `3208` 첫 표 `Current Day Slaughter`의 `Chicken (Young) / WTD`는 `주간도축량` 열에, Slug ID `3646` 첫 페이지 `WOG Trading by Size`의 `National Composite WOGS / Wtd Avg`는 `미국(cents/lb)` 열에 입력합니다. 천두·단위·원화 환산 등 양식에 있던 계산식은 변경하지 않습니다.

소-호주 시트는 목요일 기준일을 사용합니다. 다음 날 금요일의 MLA National Slaughter Cattle 표 `합계 / Count`를 `도축두수(두) / 호주` 열에 입력하고, 해당 목요일의 MLA EYCI를 `EYCI / 호주(센트)` 열에 입력합니다. AUD/KRW 매매기준율과 양식의 기존 천두·AUD·원화 환산 수식도 함께 갱신합니다.

닭-브라질 시트는 주차 행의 금요일과 같은 날짜를 CEPEA 동결 닭고기 가격 시리즈에서 찾아 `À vista R$`(R$/kg)만 입력합니다. BRL/KRW 매매기준율도 함께 입력하며, 양식의 기존 `브라질(R/kg) × 환율` 계산식으로 원화 가격을 갱신합니다.

소-미국의 `usda 수정`은 수정 후 값입니다. 다음 주 뉴스의 전 주 도축두수가 이전 주의 도축두수와 다를 때만, 이전 주 행의 `usda 수정` 칸에 그 값을 기록합니다.

## 참고 사항

### 축산 기사 초안의 문체와 선정 기준

- 사용자 제공 2026-08-13~2026-09-17 보고서 6개의 국가·축종별 문체 예시 **72개(12항목 × 6주)**를 기본 참고 자료로 유지하며, 공개 게시판에서 확인한 선별 예시와 출처 근거는 `report_template/article_editorial_examples.json`에 저장합니다. 파일명 20260904 문서의 내부 보고일은 9/10입니다. 기사 주제와 사실 구조에 맞는 소수의 예시만 골라 번역·압축 시 참고합니다. 모델 가중치 재훈련이 아닌 참고 예시 적용이며, 과거 사건·수치를 새 주차 사실로 재사용하지 않습니다.
- 기존 소고기 문체와 축종별 보고체 예시를 적용해 핵심 이슈와 **원문에 명시된 원인·시장 영향**을 요약합니다. 같은 주간 생산·도축 수치를 반복하는 후보보다 소비자가격·대체소비·교역정책·수출입·운송비·인력·산업구조의 중요한 변화를 우선합니다. 영어·포르투갈어·일본어 원문은 한국어로 작성하며, 요약 본문은 공백 포함 **현지동향 40~95자, 국내기사 40~80자**입니다(제목·매체·날짜·현지동향 접두어는 별도). 국내기사도 ‘이어간다·시사한다·전망된다’ 대신 ‘지속·시사·전망’ 등 명사형 보고체로 끝냅니다.

### 기사 반영 HWPX의 서식

- 사용자가 올린 가격 현행화 HWPX 자체를 양식으로 사용합니다. 원본 파일은 덮어쓰지 않고, 새 파일의 현지동향 8개·국내기사 4개 위치만 교체합니다.
- 현지동향 본문과 접두어의 **`(현지동향)` 전체는 휴먼명조 13pt**, 현지동향의 그 외 완결된 괄호는 11pt입니다. **국내기사 제목·매체명·날짜·요약은 괄호 안까지 전부 한양중고딕 12pt**로 통일하고, 한글·영문·숫자 등 언어별 글꼴도 중고딕으로 맞춥니다. **국내기사 네 제목은 매체·날짜까지 모두 굵게·검정 실선 밑줄**을 적용합니다. 기존 양식의 닭·계란 제목이 일반체이더라도 제목 전용 복제 서식에서 동일하게 보장하고, 요약 본문 서식은 바꾸지 않습니다. 과거 run 길이에 따라 새 문장을 배분하지 않아 숫자 중간의 글자 크기가 달라지지 않습니다.
- 기사 전용 서식의 장평·상대 크기는 언어별 100%, 글자 위치는 0으로 고정합니다. 현지동향은 한글·영문·숫자·한자·기호·사용자 언어까지 휴먼명조, 국내기사는 모두 한양중고딕으로 통일합니다. 업로드 양식에 없는 언어별 글꼴 정의는 기존 해당 글꼴 정의를 복사해 추가하며, 원본 공용 서식·가격·그래프는 변경하지 않습니다.
- 현지동향 접두어는 `- (현지동향)`입니다. **자간 0**에서 실제 칸 너비 100%를 기준으로 확인하고, 넘칠 때만 같은 사실을 유지하는 정형 문구 축약을 먼저 시도합니다. 요약은 필요한 최소한의 자간만 조정하며 **-20보다 낮추지 않습니다**. **12pt 국내기사 제목만 별도로 최저 -30까지 허용**하여 한 줄에 들어가는 가장 덜 압축된 값을 선택합니다. 짧은 본문·제목은 자간 0을 유지하며, 그래도 맞지 않는 제목은 생략·글꼴 축소 없이 자연스럽게 줄바꿈합니다. 요약의 두 줄 허용은 미국 소·미국 닭에만 적용합니다. 나머지 10개 요약이 -20으로도 맞지 않으면 수치·단위·방향·조건을 보존한 한 번의 AI 교정을 시도하고, 그래도 넘치면 완료 처리하지 않고 구체적인 줄 수 오류를 표시합니다. 이 미완료 항목은 한글 반영에서 빈칸으로 처리할 수 있습니다.
- 초안 완료 전에는 기본 보고서의 글꼴·숫자 폭·괄호 크기로 줄 수를 보조 검사하고, HWPX 반영 시에는 업로드 파일의 실제 칸 너비로 다시 검사합니다. 로컬 캐시를 사용하는 읽기 전용 검사이며, 이미 맞는 문구는 추가 AI 호출·검색 없이 통과합니다. 두 줄 허용 현지동향은 빠른 내어쓰기(Ctrl+Shift+Tab)처럼 `(현지동향)` 시작에 맞춥니다. 원본 첫 줄 위치·줄간격·정렬은 유지하고 해당 기사 문단만 여백 속성을 복제합니다. `python-hwpx==6.8.0`은 줄 경계 측정용이며 원본 문서를 다시 저장하지 않습니다.
- 국내기사 제목 뒤의 ` - 머니투데이`처럼 구분자로 붙은 매체명이 인용 괄호의 매체명과 정확히 일치하면 제목에서만 제거합니다. 실제 제목에 쓰인 매체명·하이픈이나 다른 매체명은 유지하고, 인용 출처 자체는 삭제하지 않습니다. 화면·복사와 한글 적용에서 같은 제목을 사용합니다.
- 국내기사 제목을 보고서에 표시할 때 내부 큰따옴표는 작은따옴표(`'`)로 바꾸고 바깥 인용부호 `“…”`는 유지합니다. 화면·후보 링크·문구 복사·HWPX에 같은 표시를 사용하며, 저장된 원제·원문 발췌·현지기사 제목은 바꾸지 않습니다.
- `식품저널 foodnews`처럼 확인된 한·영 중복 매체명만 `식품저널`로 정리합니다. 굵은 한양중고딕 HFT의 실제 한글 추가 글자 폭(글자당 0.05em)도 계산하여, 일반 글씨의 폭으로 제목이 한 줄이라고 오판하지 않습니다. 다른 글꼴·일반 본문에는 이 보정을 적용하지 않습니다.
- 원본 문단 줄간격은 유지합니다. 지정된 HFT 글꼴의 영문·숫자·공백 폭은 실제 한글 PDF 내보내기에서 계측한 폰트 폭을 사용합니다(한양중고딕 공백 0.5em 등). 알 수 없는 글자/글꼴은 기존 보조 측정으로 돌아갑니다. 임의의 4~7% 안전 여백을 빼지 않으며, 실제 표시를 보조 추정만으로 보장하지 않습니다.
- 소·돼지 다음에 있는 기존 두 번째 페이지 제목의 페이지 나눔을 유지합니다. 가격 표·그림·그래프 크기와 기존 공용 글자 속성은 바꾸지 않습니다. 글자 폭과 예상 줄 수는 보조 추정값으로, 실제 페이지 수는 한글 프로그램에서 확인해야 합니다. 글꼴·한글 버전·긴 제목에 따라 줄바꿈이 달라질 수 있습니다.
- v8부터 정형 원문 압축·번역 결과의 바로 사용·AI 작성·한 번의 교정·이전 국내기사 경로 모두에 최소 40자 검사를 적용합니다. 국내기사의 알려진 긍정 종결만 의미를 유지해 명사형으로 바꾸며, 부정·조건부·알 수 없는 동사는 원문 근거로 재작성합니다. 종결 변환 후 길이를 다시 검사하고, 원문에 없는 수치·원인·전망이나 공백·상투어로 길이를 늘리지 않습니다. 너무 짧은 교정 결과는 완료 처리하지 않습니다. 현재 브라우저 저장 키는 위의 v19 기준을 사용하며, 이전 버전 초안을 새 기준에서 재사용하지 않습니다(기존 저장값은 삭제하지 않음).

- 한국어 원문은 수치와 의미를 보존한 완결 문장 압축을 먼저 시도합니다. USDA 육계 종란 입란수·계란 생산량·닭고기 냉동재고, MLA 가축시장 출하두수·사육두수 추정, EU 돼지 도축·가격 추세 등 정형 문장은 원문 수치·단위·증감 방향을 추출해 한국어로 옮깁니다. 가격과 두수, 전주비와 전년비, 검토 중인 정책과 확정된 정책을 혼동한 문장은 완료로 표시하지 않습니다. 이 규칙에 맞지 않는 외국어 기사는 로컬 AI로 번역·요약하며, 문장이 검사를 통과하면 추가 AI 재작성을 생략합니다. 관련 기사·추천 기사와 발행사 자체 AI 요약 영역은 원문 근거에서 제외합니다.

### 생성 속도 최적화

- 기사 요약은 확인된 원문에 직접 적용 가능한 통계·수급·교역 규칙을 먼저 사용하고, 맞지 않는 기사만 로컬 AI로 번역·작성합니다. 과거 기사나 수치를 고정해 채우지 않습니다. 짧은 프롬프트(관련 문체 예시 1개·집중 원문)와 128개 출력 토큰 상한을 사용하며, 모델 호출은 항목당 최대 2회·실제 요청 시간 최대 45초, 전체 실행의 모델 처리 기회는 180초로 제한합니다. 외부 원문 조회·OCR·추가 후보 확인 시간은 별도이므로 전체 작업의 180초 완료를 보장하지 않습니다.
- 검색은 제목의 국가·축종과 시장 변화를 우선하고, 행사의 소개·정치적 논평·타 축종의 배경 수치·키워드 목록을 요약 입력에서 분리합니다. 정형 요약은 다른 AI 요청이 끝날 때까지 기다리지 않고 바로 표시합니다. 같은 주차의 검증된 국내 복합 기사는 축종별 본문을 재검증해 재사용하며, 이전 주차로 기간을 늘리지 않습니다.
- 최소 40자에 조금 못 미친 완결 문구(34~39자)는 ‘전년비→전년 대비’처럼 기존 표현만 풀어 쓸 수 있습니다. 새 사건·원인·숫자를 덧붙이지 않으며, 길이·원문·줄 수 검사에 실패하면 계속 재생성하지 않고 이유를 표시합니다. 실행 후 `output/article_diagnostics_<작업ID>.json`에 시간·호출 수·검증 실패 이유·공개 출처만 남기고, API 키·요청 헤더·전체 기사 본문은 기록하지 않습니다. `output/`은 Git에서 제외됩니다.
- 최대 6개 수집 작업을 병렬 실행하며, 미국 소·돼지는 같은 USMEF PDF를 한 번만 읽습니다. CPU 기반 로컬 AI와 미국 원문 OCR은 서로 경쟁하지 않게 OCR을 먼저 마치고, 다른 원문 검색은 AI 요약과 겹쳐 수행합니다. 국내 검색은 축종별 기본 3개와 짧은 보완 3~4개 질의를 병렬 비교하며, MLA는 발행일이 맞는 뉴스 카드만 확인합니다. 로컬 AI 생성과 공유 OCR 엔진은 각각 한 번에 한 요청만 처리하며 기사 초안 중복 실행을 막습니다.
- 공개 HTML은 5분간 메모리에 보관하며, 새 파서를 생성해 캐시 원본을 보호합니다. 검증을 통과한 요약은 동일 원문·제목·옵션에 대해서만 1시간 재사용합니다. 원문이 달라지면 다시 요약하며, 실패한 요약은 캐시하지 않습니다. 캐시는 서버 재시작 시 초기화됩니다.
- OCR은 CPU 스레드를 최대 4개로 제한해 로컬 AI/Excel과의 과도한 CPU 경쟁을 줄입니다. 선택 가능한 PDF 텍스트가 있으면 OCR을 생략하고, 이미지형 PDF는 기존 OCR 경로를 유지합니다.
- Excel 비교 산식은 행 단위로 한 번 읽고 달라진 셀만 수정합니다. 값·산식·표시단위 계산 및 Excel의 정상 저장 경로는 유지합니다.
- Excel 저장 세션에서 그래프 6개를 함께 내보내 `output/<보고서 이름>.charts/`에 둡니다. 파일 크기·수정 시각·그래프 위치가 일치하는 캐시만 HWPX에 사용하며, 실패 시 기존 별도 Excel 내보내기로 복구합니다.
- 한글 표는 Excel 전체 대신 필요한 두 시트의 계산 결과만 읽습니다. USDA·일본 그래프 다운로드는 서로 및 Excel 그래프 처리와 겹쳐 실행하며, 원본 양식의 그림 크기·표 서식은 유지합니다. 브라질 수집도 다른 기관 수집과 함께 시작합니다.
- 경과시간 화면은 전체 시간만 표시합니다. 세부 병목 진단은 별도 도구 `python work/profile_generation.py article --date 2026-09-24 --repeat 2` 또는 `python work/profile_generation.py excel --excel <입력.xlsx> --output <별도출력.xlsx>`로 수행합니다. 외부 응답·PC 부하·빈 주차 수에 따라 소요시간은 달라집니다.
